# 08. チューナー(復調IC・RFチューナーIC)とのI2C通信

Debian上から、**復調ICと、その奥のRFチューナーICのレジスタを読める**ところまで確認した。アンテナ未接続の状態で調べたため、選局・ロックは未確認。

## 結論

| 項目 | 内容 |
|---|---|
| 経路 | 公式ドライバ(`xcode4drv`)の `CMD_I2C_COMMAND_STREAM`(ioctl cmd 0x1b)。MCUと同じ経路([docs/06](06_mcu_watchdog.md))。`/dev/mem`直叩きは使わない |
| I2Cバス | **ブロック1**に2デバイス: 8bit表記 `0x20`(7bit `0x10`)と `0x22`(7bit `0x11`)。どちらもレジスタ空間(0x00〜0xff)が読める |
| バス0 | `0x20`=MCU(既知)と `0x2a`(7bit `0x15`)。`0x2a`は何を読んでも全て`00`(正体不明。読み出し専用か、無関係のデバイス) |
| 推定される正体 | 復調IC=**東芝 TC90532系**(初代nasne分解記事に「TC90532XBG」とある。ISDB-T/S両対応で、T用とS用が別I2Cアドレスに見える作り)。7bit`0x10`/`0x11`が隣り合うのは、同系統の TC90522 をT用・S用の2アドレスで扱う配置に似ている(記憶に基づく推測で未確認)。**どちらがT/Sかは未確認** |
| レジスタの挙動 | 大半は設定値で読むたびに同じ。`0x20`では`0x90〜0x9a`と`0x8e`、`0x22`では`0x70`/`0xb8〜0xcf`/`0xe9`が読むたびに変わる(ノイズ/AGC/ステータス系。アンテナ無しなので当然) |
| 副作用 | 読み取りのみ(レジスタ番号を書いてから読む)。ファームの稼働状態(`fw_state=0`)も、その後のMCUウォッチドッグも影響なし |

RF側のチューナーICは、復調ICのI2Cゲート(パススルー)の奥にいる。下の「パススルーの手順」参照。

## ツール(`scripts/tools/`)

どちらも libc 不使用の静的MIPSバイナリ。ドライバ(`rc.xcode4`)がロード済みで、ファームが動いていること(`boxioctl 103 b0 -d 0x2c`の`+0xa4`が0)が前提。

```
i2cscan <block 0|1> [hz]                      # 全アドレスを1バイトreadして、ACKするものを一覧(読み取りのみ)
i2cx <block> <addr8hex> r <n>                 # n バイト読む
i2cx <block> <addr8hex> g <reg>... <n>        # regを書いてからn バイト読む
i2cx <block> <addr8hex> d <reg0> <count>      # レジスタ空間のダンプ
i2cx <block> <demod8> p <tuner8> <n> [pre...] # 復調IC経由(パススルー)でRFチューナーICをnバイト読む
i2cx <block> <addr8hex> h <reg> <n>           # [reg]を書き(stopなし)repeated startでn バイト読む(純正の復調IC読み出しと同じ)
i2cx <block> <addr8hex> w <byte>...           # 書く(未検証のICには使わないこと)
i2cx -b                                       # 標準入力から1行1コマンド(上と同じ引数、`sleep <ms>` も可)を連続実行
```

使用例(復調ICのレジスタ全ダンプ):

```
./i2cx 1 20 d 0 256
./i2cx 1 22 d 0 256
```

## 純正ソフトのI2C呼び出し(`dtvtuner` のデコンパイルで特定)

dtvtunerの下位ボードI2C層(`FUN_005e337c`=書き、`FUN_005e3688`=読み。引数は `(ctx, バス, 8bitアドレス, データ, 長さ, start, stop)`)の呼び出し元から、
**バス1の `0x20`/`0x22` を実際に叩いているコード(0x460e5c〜0x462034付近)**を特定した。

| 操作 | 手順(8bitアドレス) |
|---|---|
| 復調ICのレジスタ書き | `[reg, data...]` を `0x20` または `0x22` に書く(`FUN_00461864`=0x22、`FUN_004619bc`=0x20。失敗時は最大3回リトライ、排他ロックあり) |
| 復調ICのレジスタ読み | `[reg]` を書いて(stopなし)、同じアドレスをrepeated startで読む(`FUN_004611c4`、`FUN_00461308`、`FUN_00461e94`) |
| ビット更新 | 読んで → マスク → 書く(`FUN_00460ff8`=0x22、`FUN_00461e94`=0x20) |
| **RFチューナーへの書き** | 復調ICに **`[0xFE, <チューナー8bitアドレス>, data...]`** を書く(`0xFE`がパススルー)。`0x22`の奥は `0xC8`(`FUN_0046144c`)と `0xC6`(`FUN_004615a8`)、`0x20`の奥は `0xC0`(`FUN_00461704`) |
| **RFチューナーの読み** | `[0xFE, tuner8, reg]` を書く → `[0xFE, tuner8|1]` を書く(stopなし)→ 復調ICを `0x23`/`0x21` 相当でrepeated start読み(`FUN_00461b14`=0xC8、`FUN_00461cd4`、`FUN_00460e5c`=0xC0) |

バス0の `0x30`(8bit)には別の2バイト書き込みの経路(GPIO拡張IC風。ポート0x11/0x12、レジスタ4/9。値`0x21`/`0x42`/`0x43`などでアンテナ給電の切替らしき動き)があるが、
**テストした基板では `0x30` はACKしない**(読み取り確認済み)ので未実装のボード向けコードとみられる。ポート番号→SoCのGPIOレジスタの対応(ポート4=`0xFC04`…ポート10=`0xFC64`(LED)…ポート0x13=`0xFCB4`)もこの関数から確認できた。

## パススルー越しにRFチューナーICを確認(実機、読み取りのみ)

`i2cx 1 <demod8> p <tuner8> ...` で、上の手順をそのまま再現して走査した(各ゲートで8bitアドレス`0x02`〜`0xFE`の全部を試し、ACKしたものだけ):

| ゲート(復調IC) | RFチューナーIC(8bit/7bit) | 読めた内容 |
|---|---|---|
| `0x22` | `0xC6` / `0x63` | レジスタ0〜7: `5f 13 30 c7 12 00 fe 1e`、以降`00`。レジスタ番号ごとに値が違う=本物のレジスタ付きIC |
| `0x22` | `0xC8` / `0x64` | レジスタ0〜3: `21 0f 50 23`、以降`00` |
| `0x20` | `0xC0` / `0x60` | レジスタ番号に関係なく常に`02`(ステータス1バイトを返すだけのIC。PLL型チューナーに多い形式) |

- 他のアドレスはすべてNACK(`rv=0x0d`)で、「ゲートが全部ACKを返す」わけではない=上の3つは実在する。
- `0x22`側に2つ、`0x20`側に1つ。dtvtunerのコードでも `0xC8`/`0xC6`/`0xC0` が使われており、一致した。
- 7bit `0x63` は、日本向けISDB-Sチューナーのオープンソースドライバ(シャープ系 QM1D1C0042 など)が使うアドレスと同じだったと記憶しているが(未確認)、レジスタの中身を既知のICと照合できておらず、**ICの型番は未確定**。
- `0x22`と`0x20`のどちらがISDB-S/Tかも未確定。「S用のチューナーが2個ある側が`0x22`」という推測が立つが、アンテナ接続後に検証が必要。

## 地デジ(ISDB-T)の選局手順(実機で動作確認済み)

ゲート `0x20`(復調IC)→ RFチューナー `0xC0`(チップID reg `0xCC` = `0x2A`)。チューナーのレジスタは「レジスタ番号+値」の組の連続で、1回の書き込み `[0xFE, 0xC0, reg, val, reg, val, ...]` に詰める。
読み出しは `[0xFE,0xC0,0xFB,reg]` → `[0xFE,0xC1]` → 読む(`i2cx ... p c0 1 fb <reg>`)。

- **初期化**: `[0xFE,0xC0,0xFF]`(リセット、10ms待つ) → 初期設定列(24MHz水晶用。76バイトで、[scripts/tools/nasne_recpt1.c](../scripts/tools/nasne_recpt1.c) の `TUNER_INIT`)
  → `[01 01 13 01]` → 復調IC `(01,40)(0e,07)(0f,10)(23,38)(4f,e5)` → スタンバイ(チューナー `[13 01]`、30ms、`[01 00 13 00]`、復調IC reg `0x03`=0xF0)。
- **選局**: チューナー `[01 01]`、復調IC reg `0x03`=0、`0x77`=3、`0x71`=0x30、`0x20`=0、`0x25`=0、`0x23`=0x39 →
  チューナーに周波数設定列(6MHz帯域) → 31ms待ち → チューナー reg `0x1A`=0x0D → 復調IC `0x23`=0x38、`0x47`=0x40、`0x01`=0x40 → reg `0x80` の bit3 が落ちる(ロック)のを待つ。
- **周波数設定列**: `(13,00)(3b,c0)(3b,80)(10,95)(1a,05)(11,N&ff)(12,N>>8)(13,01)`。`N` = 周波数[MHz]×64を四捨五入(例 473.143MHz → `0x7649`)。
  UHF chN の中心周波数 = 473.142857MHz + 6MHz×(N−13)。
- **状態**: 復調IC reg `0x80` の bit3=0 かつ bit7=0 でロック、reg `0x82` = AGC、reg `0xB0`〜`0xB9` = TMCC情報、reg `0x8B`〜`0x8D`(24bit)= C/Nの元データ。
  C/N[dB] = `((((f×2.4e-5 − 0.0016)×f + 0.0398)×f + 0.5491)×f) + 3.0965`、`f = 10×log10(5505024 / 値)`(純正と同じ換算)。

共同受信設備(ケーブルテレビの同軸)につないだ環境で、UHF 13〜62 を順に選局したところ、いくつかのチャンネルでロックし、C/N 32〜35dB・TMCC取得済みだった。
PCから試すツール: [scripts/nasne_fe.py](../scripts/nasne_fe.py)(`--host <ip> t-init / t-tune <ch> / t-scan / t-status / t-standby`。nasne側に `i2cx`(バッチモード `-b` 対応版)が必要)。

## 衛星(ISDB-S)側の手順(純正コードの解析結果。実機のBS/CSアンテナ無しの環境で試験したため**動作未確認**)

- ゲート `0x22`(復調IC)→ RFチューナー `0xC6`(16MHz水晶、PLL分周型、レジスタ0〜7)。`0xC8` は初期化で `[0x02, 0x53]` を書かれるだけの別のIC(役割不明)。
- **初期化**: チューナーreg0〜7 = `03 13 dc 85 12 01 e6 1e`、復調IC `(03,01)(06,40)(07,01)(08,00)(10,b1)(11,40)(85,7a)(8e,05)(a3,33)(a5,c0)`、`0xC8` に `[02,53]`、最後にスタンバイ(復調IC reg `0x13`=0x80、`0x17`=0xFF)。
- **選局**(引数は衛星RF周波数[kHz]。IF = RF − 10,678,000kHz): チューナー電源ON、復調IC reg `0x13`=0・`0x17`=0、`0xA5`=0x80または0xC0、`0x07`=1、`0xA6`=4、`0x03`=1、`0x0A`=0、`0x11`=0、`0x03`=1 →
  チューナーPLL設定(帯域で `(L28,L24,base)` = IF<1,022,001: (1,0,2) / <1,324,577: (1,1,2) / <2,046,001: (0,0,1) / それ以上: (0,1,1)、`P=2^base`、`s2` = `160/2^k`(k=1..4)のうち `10P` に最も近いものの `k-1`、
  `N = 2^(s2+1)×IF×P×10/16000`、`t0=N+5`、reg2=`(t0/10)&0xFF`、reg3=`(L24<<5)|(L28<<4)|(s2<<6)|(t0/2560)`、reg5のbit2を立てて落ちるまで待つ) →
  復調IC `0x0A`=0xFF、`0x11`=0x40、`0x03`=1 → reg `0xC3` の bit4 が落ちるのを待つ(TMCC有効)。
- **状態**: reg `0xC3` bit4=0 でTMCC有効、reg `0xBA`&0x7F = AGC、reg `0xBC/0xBD` = C/N の元データ。
- 地デジのアンテナ入力は生きているが、BS/CS入力の信号が無い環境(AGC最大、TMCC無効)でしか試していない。BS給電(アンテナ電源)の制御箇所は未特定。

## 分かったこと・分かっていないこと

- 分かった: 復調IC・RFチューナーICとのI2C通信、地デジの選局とロック・C/N取得、**TSの取り出しとB-CAS復号まで**([docs/11](11_tv_streaming.md)、[docs/12](12_ts_and_bcas_decrypt.md))。
- 分かっていない: 各ICの型番、チップIDレジスタの位置(復調ICのみ)、BS/CSの動作、バス0 `0x2a` の正体、ファーム(MIPS側)との同一I2Cブロックの排他(ホストから書くと衝突しうる)。

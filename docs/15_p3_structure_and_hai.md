# 15. p3(録画領域)の初期構造と `.hai`(v1.00 なしで空のHDDから v2.60 を起動する仕組み)

[docs/04](04_hdd_recovery_guide.md) の手順の裏付けです。空のXFSのp3だと v2.60 の公式アプリが止まる理由と、v1.00 に頼らず p3 を用意する方法を、
逆アセンブルと実機での切り分けでまとめます。**実機1台での確認**です(別の本体では未検証)。

## 1. 何が起きていたか

v2.60 は、p3(HDDの3番目の区画、XFS)に次の「初期構造」が無いと、起動の約35秒後に機体が固まります
(PWR/REC赤点灯・LAN点灯、ネットワークも切れる。再起動ループではない)。**v1.00 はこの構造を自分で作る**ので、従来は v1.00 が必要でした。

p3 に必要なもの(実機で、足りないものを1つずつ足して確認):

| p3 の中身 | 結果 |
|---|---|
| 生成した `.hai` のみ | ❌ 固まる |
| 公式の初期構造一式 + 生成した `.hai` | ✅ 起動(**生成した `.hai` が受け入れられる**) |
| `.hai` + `00000021/` + `opt/CMA` + `setup` + `share`(`00000015/` 無し) | ❌ |
| 上 + 空の `00000015/00`〜`95` | ❌ |
| 上 + `00000015/10000000.dat` と `10000001.dat` | ✅ 起動 |

つまり必要なのは **`.hai` の2ファイル、録画DBの雛形2ファイル、空のディレクトリ群**。`00000015/NN/*.dat`(各ディレクトリの小さなDB)は無くても起動します(アプリが作る/不要)。
`nasne_hdd_rebuild.py p3init` が、これらを空のp3に作ります。

## 2. `.hai`(HDD登録情報)

`00000000.hai` と `00000001.hai`(p3直下、同じ内容の予備。**どちらか一方が有効ならよい**)。`libsechdd.so` と `dtvtuner` の逆アセンブルで形式が分かり、
実機の `.hai` を復号して検証済みです(`scripts/nasne_hai.py show`)。

- **ちょうど65536バイト**。0バイトや短いファイルは読込側が弾きます。
- 256バイトの文字列枠が4つ(NUL終端): 本体の個体ID(16桁の16進、`00110022.dlm` のchipidと同じ)/ HDDのベンダ名(`ATA`)/ モデル名(先頭16文字)/ シリアル番号。
  オフセットは 8537 / 5649 / 11375 / 4259。
- 難読化は、ファイル全体を **255バイト周期の鍵でXOR**。鍵 = ファイル内の「鍵領域」(オフセット21064から255バイト、平文のまま置く)と、ファーム内の定数255バイトのXOR。
- 検査和: オフセット144の4バイトに、先頭32768バイトを16ビット小エンディアン語として足した和(和を取るときは144の4バイトを0とする。難読化後のバイト列に対して計算)。
- 残りは乱数でよい(公式は `rand()`)。
- 読込側の照合は **個体IDの先頭一致** と **シリアルの先頭一致** だけです。HDDを入れ替えると、シリアルが合わなくなって(登録情報が一致せず)使えなくなります。

PCでUSB-SATAアダプタ越しにHDDを見ると、ベンダ・モデルがアダプタの名前になります。本体側(SATA直結)では `ATA` と、モデル名の先頭16文字に見えるので、
ツールは `lsblk` のモデル名から本体側の見え方に直して書きます。

## 3. 録画DBの雛形

`00000015/` は録画コンテンツのDB(`pvr_db_manage`)です。直下の `10000000.dat` と `10000001.dat`(100KB、同一内容の2重コピー)が無いと起動しません。

- 100KBの大半はゼロで、実データは先頭121バイト。形式は、マジック `a17e4d13` / 長さ(`0x71`)/ 4バイト / 固定8バイト / 暗号化された本体。
- **別のHDD2台(機種・シリアル・容量が違う)で v1.00 が作ったものが、バイト単位で完全一致**しました。HDDに依存しない固定の雛形です。
  本体(個体ID)に依存するかは、本体が1台なので **未確認**です。
- 暗号は未解読です(ファームの Blowfish 鍵での既知のモード総当たりでは平文化できなかった)。ツールは121バイトを定数として持っています。
- 各ディレクトリの `NN/*.dat`(約150バイトの同形式のDB)も存在しますが、アプリが作るので用意は要りません。

## 4. 調べ方(再現したい人向け)

- 公式のまま起動して中を見るための `.dlm` を作れます: `python3 scripts/stage1/make_stage1_dlm.py build --official <そのHDDの00550066.dlm> --out debug.dlm --mode debug`。
  `eth0` を上げて telnet、公式アプリが呼ぶ `halt`/`reboot` を無効化、HDDの sys1 に状態ログ(`dbglog.txt`)を2秒ごとに書きます。
  公式の `rcS` は `eth0` を上げません(ネットワークは公式アプリが後から上げる)。そのため、デバッグには `eth0` を自前で上げる必要があります。
- 固まった機体は、電源を入れ直すと戻ります。ログはHDDに残るので、PCに戻して読めます。
